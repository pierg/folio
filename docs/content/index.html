folio turns a coding agent into the librarian of a knowledge library that lives inside a project, or on its own.

Every document has one genre, which fixes its job, its voice, its format and its checks. Documents link to each other, and maps give a reader the way in. You talk to your agent; it follows folio's seven skills and runs the gate before every commit.

This documentation is itself a folio library. Every page you read here was written and checked the way yours would be.

  • You askIn plain words, to the coding agent you already use. The folio command exists, but only the skills call it.
  • The library is filesPlain HTML and Markdown in a folder in git. Reading a page needs no build step.
  • Nothing lands uncheckedEvery change passes folio check before it is committed.
  1. Ask. "Add a concept for the gate", "file this paper", "tidy the maps". The agent picks the skill that covers it: set-up, configure, write, organise, address, run or publish.
  2. Write. The write skill picks the genre, writes in its voice, links the concepts it uses, flags what goes beyond its sources and puts the document on a map.
  3. Check. The gate reads every document: links resolve, maps list what they should, frozen records are unchanged, each genre's checks hold.
  4. Read and answer. The library renders as a site. A comment on a passage is saved in a file beside the page, and the address skill answers it on that page.
