Ask for a document in plain words

Say what you want: "add a concept for eventual consistency", "write a note on why we pinned the parser", "log that we chose Postgres". The agent matches the request to a genre and confirms it in one line. It asks only when two genres fit equally well.

A genre is a kind of document. It fixes the document's job, its reader, its voice and its format. The core has eight.

You want to pin down what a term means, so other pages can point to it. Which genre?
A concept. It holds the definition once, and every other mention links to it.

What the agent does to write it

The agent follows the write skill. Follow one request through it: "add a concept for eventual consistency". On the right, the document fills in as each step adds its part.

  1. Step 1 · Pick the genre

    The request names a term to define, so the genre is a concept. The agent says so in one line and carries on. It would ask you only if a note fit just as well.

  2. Step 2 · Check for a home

    folio search eventual consistency

    Before writing, the agent searches the library. If the term already lives in some document, it revises that one or cites it. A fact gets one home, never two.

  3. Step 3 · Open the document

    folio new concept eventual-consistency --title "Eventual consistency" --description "When replicas of one store agree, and why they may not yet."

    The document is created from the genre's skeleton, in the genre's folder. The title and the one-line description go into the metadata, where the shell, search and link previews read them.

  4. Step 4 · Write it

    The agent reads the genre's card and writes the body in its voice. For a concept, that means one definition, set apart, then what the term is not and where it is used. The body starts with content, never with its own title.

  5. Step 5 · Link and cite

    Every term that has a concept of its own links to it, and every other document is cited by its id. The agent runs folio cite to get the right markup, so a citation always takes the same form.

  6. Step 6 · Flag what needs you

    folio annotations add eventual-consistency --kind flag --label "unsourced" --quote "..." --body "No source gives this timing: cite one or cut it." --author agent:writer

    Where the agent states something its sources do not support, or a number it could not check, it leaves a flag on that passage saying what you have to decide. Its own examples, framing and wording raise none, so the flags that reach you are few.

  7. Step 7 · Put it on a map

    folio map add concepts eventual-consistency

    The new document gets a row on a map, where a newcomer would look for it, so it is never an orphan.

  8. Step 8 · Run the gate

    folio index
folio check

    The indices are rebuilt and the gate runs. The agent fixes everything it names and runs it again, until it passes.

  9. Step 9 · Commit

    The agent adds exactly what it touched: the document, its comment file, the indices. Then it commits, and tells you in a few lines what changed, where it lives, and what flags wait for you.

The agent wrote a claim its sources do not support. How will you know?
It leaves a flag on that passage saying what to decide, labelled "unsourced". Flags wait for you on the rendered page; an example of its own raises none.
You ask for a concept, but a note already defines the term. What does the agent do?
It revises the note or cites it, instead of writing a second definition. The search in step 2 is there to catch exactly this.
