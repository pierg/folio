Hand your agent the setup prompt

folio is installed by your agent, not by you. Open your coding agent in the project where the library should live, and paste the setup prompt from SETUP.md.

The prompt tells the agent to install the engine, confirm it runs, and then follow the set-up skill. A skill is a written procedure the agent reads before it acts. Set-up is the first of seven.

Or install the engine yourself

If you prefer to install the engine first, run one of these. The package is folio-kb; the command it installs is folio.

uv tool install folio-kb
pipx install folio-kb
pip install folio-kb

Then ask your agent, in plain words, to set up folio here. It finds the set-up skill and carries on from the questions.

Either way, you do not run folio again yourself. The skills call it, the way an agent calls git.

What is the package called, and what is the command called?
The package is folio-kb; the command it installs is folio.

The questions come in one message

The agent asks you at most three questions, all in one message: what the library is called and who reads it, where it should live, and which packs to switch on. A pack adds genres and rules for one kind of work, such as a lab's results.

Every question comes with a default, so "defaults" is a full answer. A question you already answered in your request is skipped.

How many rounds of questions does set-up take?
One. The agent asks everything it still needs in one message, and skips what you already said.

What set-up leaves behind

Set-up makes a library in the folder you chose, and commits it. Step through what the agent runs, and watch the project fill in. Each step lights the files it writes.

  1. Step 1 · Confirm the engine

    folio version

    The agent checks that the engine runs and tells you its version. If it does not run, the agent stops and gives you the install line. Nothing is written yet.

  2. Step 2 · Create the library

    folio init docs --name "Field notes" --purpose "What we learned building the importer"

    One command writes the charter, the home page, the asset folders, a .gitignore and the generated indices, and copies the seven skills to the project's root. The home page takes its title from the name.

  3. Step 3 · Finish the charter

    folio config set reader "The team, who know the importer's code"
folio pack on lab

    The reader goes into the charter, and each pack you chose is switched on there. Only the set-up and configure skills write the charter, and always through the command, so every change is visible.

  4. Step 4 · Record the setup

    folio journal add --title "Library set up" --description "Notes on building the importer, for the team" --body "..." --kind decision --about home

    The library's first journal entry is a decision: what the library is for, who reads it, which packs are on, where it lives. folio init writes no entry, so this is the first.

  5. Step 5 · Run the gate

    folio index
folio check

    The indices are rebuilt to include the new entry, and the gate runs. A new library passes it: it starts clean.

  6. Step 6 · Commit

    The agent adds exactly the files set-up wrote, never everything in the folder, and commits them with one line saying the library was set up. Then it tells you, in two lines, what you can now ask for.

Which file holds what the library is for, and who writes it?
folio.yaml, the charter. Only the set-up and configure skills write it, and each change is recorded in the journal.
You open the library right after folio init, before set-up has finished. Is there a journal entry yet?
No. folio init writes none. The set-up skill adds the first one, a decision recording the setup, before it runs the gate.
