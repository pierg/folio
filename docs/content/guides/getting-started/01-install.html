Hand your agent the setup prompt

folio is installed by your agent, not by you. Open your coding agent in the project where the library should live, and paste the setup prompt from SETUP.md.

The prompt tells the agent to install the engine, confirm it runs, and then follow the set-up skill. The agent asks you at most three questions in one message: what the library is called and who reads it, where it should live, and which packs to switch on. Every question comes with a default, so "defaults" is a full answer.

How many rounds of questions does set-up take?
One. The agent asks everything it still needs in one message, and skips what you already said.

Or install the engine yourself

If you prefer to install the engine first, run pip install folio-kb, or uv tool install folio-kb. The command it installs is folio. Then ask your agent, in plain words, to set up folio here. It finds the set-up skill and carries on from the questions.

Either way, you do not run folio again yourself. The skills call it, the way an agent calls git.

What is the package called, and what is the command called?
The package is folio-kb; the command it installs is folio.

What set-up leaves behind

Set-up makes a library in the folder you chose and commits it:

docs/
  folio.yaml        the charter: name, purpose, reader, packs
  content/
    index.html      the home page
    journal/        one file per entry; the first records the setup
  assets/           figures, the bibliography, data
  .folio/           generated indices, committed
.agents/skills/     the seven skills, at the project's root

It ends by running the gate, which passes on a new library, and by telling you in two lines what you can now ask for.

Which file holds what the library is for, and who writes it?
folio.yaml, the charter. Only the set-up and configure skills write it, and each change is recorded in the journal.
