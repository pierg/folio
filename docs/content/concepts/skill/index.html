Skill
A skill is a written procedure a coding agent follows to change a library: when to use it, its rules, its steps, when to stop, and when it is done. folio ships seven: set-up, configure, write, organise, address, publish and run.

The person using folio talks to their agent in plain words, and the agent picks the matching skill. The skills call the folio command the way an agent calls git, so the person never needs to learn it.

The set is fixed. What is specific to a kind of document lives in its genre's card, and what is specific to a procedure lives in a workflow, so neither needs a skill of its own.

Seven skills around one command

Every skill acts on the library through the same command. Pick a command to see which skills call it.

Who talks to whom

  1. The person

    Asks in plain words: "add a concept for this", "tidy the maps".

  2. The agent

    Matches the words to a skill by its description, and reads it.

  3. The skill

    Its steps, rules and stops, followed in order.

  4. folio

    The command the skill calls, ending at the gate.

Every skill starts the same way

This is why a new genre, workflow or pack never needs a new skill: each one reads what the library offers before it acts.

  1. Find the library: the nearest folio.yaml.
  2. Read the charter.
  3. List the genres and workflows available, from the library, its packs and the core.
  4. Read the card for the genre in hand.
The trap: thinking a new kind of document needs a new skill. Every skill starts by reading the charter, the genres and the workflows, so it already knows what a new genre or pack adds.

Related

Every skill that changes a document ends at the gate, then commits exactly the files it touched.

Where they live

The skills are installed in a library's .agents/skills/, for any coding agent that reads that folder.
