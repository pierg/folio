Journal
The journal is a library's dated record of what happened and what was decided. Each entry is its own short Markdown file with a date, an optional kind, and the ids of the documents it is about.

Documents say what is true now; the journal says when it changed and why. An entry shows on every document it names, and the shell renders all entries as one timeline that filters by kind, tag, date or document.

Why one file per entry

A single log file would be shorter to read in an editor. One file per entry buys three things the log cannot give.

One file per entry

Two agents writing at once never touch the same file, so they never conflict. Every entry has its own address, so it can be linked and searched on its own. Every entry is a permanent record, and the gate compares each file with its first commit.

One log file

Every new entry edits the same file, so concurrent writers collide. An entry is a heading inside a long page, not a document, so nothing can name it in about or show it on a page. The file changes every day, so no line in it can be held to its first commit.

Kinds

A kind is optional. The shell filters by it, and two kinds change what readers see on the document they name. Kinds are an open set: the core has four, a pack adds its own while it is on, and the charter adds more under journal.kinds.

The core's four

decision
A choice that binds later work.
lesson
Something learned the hard way.
correction
Says a document was wrong and what is true instead; shows as a banner on it.
retraction
Withdraws a record, which is then marked retracted.

Added here by the lab pack

lock, run, kill, instrument and pivot. An entry with no kind is a plain event, such as a source ingested or a result recorded.

The trap: writing a decision only into the page it changed. The page will be revised again and the reason lost. The decision goes in the journal, about that page.
