Map
A map is a document that lists other documents in the order to read them, each row with an optional one-line reason to follow it. The maps the charter names as home maps are the library's topics, drawn on its home page.

A library has no folder tree for a reader to browse; folders follow genres, not subjects. Maps are the structure instead. A document can sit on several maps, and a map can list other maps, so one library can have as many front doors as it needs.

What falls under a topic follows from the maps. Nothing on a document declares its topic.

How the maps nest, in this library

The home page is a map. The charter names four home maps under home.maps, and each lists its rows in reading order. Pick a topic to focus on it, as the Focus control in the top bar does: what falls under it stays lit, wherever it sits.

Maps, not folders

Folders follow genres

Every concept is under content/concepts/, every entry under content/entries/. That tells the engine what a file is. It tells a reader nothing about where to start on a subject.

Maps follow subjects

A map picks documents of any genre, puts them in order, and says why each is worth following from here. The same document can be on a map for newcomers and on a map for one project.

What one row holds

A link
To the document. The shell draws the link's text from the document's title, so a renamed document reads right on every map.
A reason, optional
One line on why to follow it from this map. Without one, the shell shows the document's description.
A place
Its order and its group heading, which the map keeps as written.
The trap: using tags as structure. Tags are facets for filtering. A reader arriving cold needs an order and a reason, and only a map gives them.

Related

The gate checks that every document except a journal entry is reachable from a map.

Who keeps them

The write skill puts each new document on a map in the same change. The organise skill moves, merges and splits maps with every link kept.
