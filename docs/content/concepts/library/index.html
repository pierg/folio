Library
A library is a folder holding a folio.yaml charter, a content/ folder of linked documents, an assets/ folder, and the generated indices in .folio/. It can be a project's docs/ folder, a notes folder, or a whole repository.

Everything folio does is scoped to one library. The folder on the right is the whole of one. Every document is under content/, one folder per genre; nothing outside it is a document.

Pick a writer to see which folders it owns. No folder has two.

Where a library sits

A library is wherever a folio.yaml is. One project can hold more than one. When a library sits inside a larger project, the charter's root: names the project root, and a path a document gives to something outside the library, such as a result's evidence, resolves from there.

A project's docs/

The library beside the code it documents. This library is one: folio's own docs/, with root: .. pointing at the repository.

A notes folder

A personal library of concepts, notes and readings, inside whatever repository holds it.

A whole repository

The repository is the library, and its root holds the charter.

One library, one scope

  • The gate checks one library.
  • The site exports one library.
  • Ids are unique within one library, whatever the genre.
  • Search covers one library, and a charter can list others to search alongside its own.
The trap: reading the library as a website. The pages are plain HTML and Markdown in git, readable with no build step. The site is one view of them, written by export.
